# WBO Arena Client

本目录是 WBOsiris 的 React/TypeScript 牌桌客户端。

对战卡面显示实例当前 X，卡牌详情列出命名计数器，含零值；牌组详情显示基础值。
录像按保存帧显示当时的计数器。对手隐藏手牌的值不会通过对局接口发送。

舍弃手牌使用目标选择与显式确认；选择过程只对行动方可见。舍弃后双方日志显示
舍弃的卡名，录像保留公开的弃牌身份，不将舍弃显示为破坏。

可启动的战场卡牌会显示操作提示，详情中的“启动”按钮直接提交服务端提供的合法动作。
费用、每回合次数与选择步骤均由规则服务决定。

```bash
npm install
npm run dev
```

默认连接 `http://127.0.0.1:8080`。部署网页端和规则服务到不同主机时，可设置：

```bash
VITE_API_BASE=https://rules.example.test npm run dev
```

同时启动项目根目录的规则服务：

```bash
go run ./cmd/wbo serve --source-root . --listen :8080
```

页面默认连接规则服务，消费 `state`、`legalActions`、`pendingChoice` 和 `events`，不实现规则判断。

视觉素材位于本项目的 `web/public/assets/`，包括牌框、职业图标、卡背和卡图。
`assets/cards/` 包含当前卡池的普通与进化原画，`manifest.json` 记录源纹理编号、
相对路径、源文件与输出文件的 SHA-256，以及转换参数。前端通过生成的
`src/generated/card-art.json` 查找图片；不依赖外部目录或运行时素材服务。

## 卡图导入

先编译卡池，再指定原始资源的导出目录。需要 Node.js 和支持 WebP 的 ImageMagick。
导出目录应包含 `analysis/cards_full.json` 与 `card-textures-resized/{Main,Token,Special}/`。

```bash
go run ./cmd/wbo compile --source-root . --output /tmp/cards.wbos cards
node scripts/import_card_art.mjs /tmp/cards.wbos /path/to/asset-exports
node --test scripts/card_art.test.mjs
```

以上命令从仓库根目录执行。导入只处理已编译卡池中的身份，按纹理呈现编号匹配普通
和进化图，不用进化卡牌的逻辑 ID 猜测文件名。原图保持比例缩至最多 636×768，
输出使用内容哈希文件名；重复导入会校验源和输出哈希，跳过相同文件并修复损坏输出。
清单在转换成功后更新，已知身份缺少原始图片会报错；没有源身份的自建测试卡记录在
`missing` 中并显示“暂无卡图”。无映射或加载失败时不会使用其他卡牌图像代替。

卡牌详情可切换进化前后的原画，战场按服务端的进化、超进化状态使用进化图。
原画切换不修改规则身材，详情中的数值明确标记为基础值。

## 页面与网络接口

顶部导航提供主页、对战、卡组、录像和房间五个页面。页面通过 `?page=` 保留当前视图；对战房间使用 `?match=`，邀请链接额外带 `join=`。

对战手牌按 `instanceId` 区分同名副本，选中、换牌和出牌均保留实例身份。
指针点击完成后才展开手牌，避免焦点事件改变按下与松开的位置；键盘聚焦也可展开，
Enter/空格选择卡牌，Escape 关闭详情并收起手牌。展开区使用固定尺寸卡牌与横向滚动，
触屏滑动不触发选择。手牌样式集中在 `src/hand.css`，在基础牌桌样式之后加载。

`src/matchConnection.ts` 统一管理对局轮询、动作和换牌请求。轮询逐次完成后再安排
下一次请求；提交动作会取消旧轮询，同一时间只允许一个写请求，过期响应不得覆盖
较新的局面。相同修订号仍可更新等待加入、换牌确认等房间状态。
每个动作与换牌请求携带 `expectedRevision`，取自客户端最后确认的 `state.revision`。
服务端在房间锁内比对修订号，过期请求返回 `result.status = "rejected"`、
`result.errorCode = "stale_state"` 及当前玩家视角的最新局面，不执行动作、不增加录像帧。
网页采用返回的局面并显示“局面已更新，操作未执行”，不会替玩家重新提交旧动作。
网页收到服务端结果后才更新手牌和资源；HTTP 错误、无效响应、断网或十秒超时
会保留最后确认的局面并重新同步，同步完成前禁用动作。写请求不会自动重发，
响应丢失时通过后续读取确认当前局面。切换房间会取消旧连接，忽略其迟到响应。

请求顺序、重复提交、错误恢复和换牌回归测试：
`node --test scripts/match_connection.test.mjs`（仓库根目录，Node.js 22.18+）。

房间相关接口：

- `GET /api/cards` 返回当前规则包中的卡牌名称、文本、费用、职业、类型、属性、组牌资格及默认练习牌组；响应不缓存。
- `POST /api/matches` 创建房间，响应包含创建者令牌与一次性邀请码。
- 创建房间时可提交 `{"deck":[卡牌ID...]}`；牌组必须正好 40 张，每张卡最多 3 张，
  使用同一职业并可加入中立卡牌，且卡牌必须存在于当前规则包并可用于构筑。衍生卡及尚未实现的卡牌不能编入牌组。
  省略该字段或设为 `null` 时使用默认练习牌组，显式空数组会被拒绝。服务端会在发放起手牌前洗牌并发出四张起手牌。
- `GET /api/matches` 查询公开房间的 ID 和等待状态，不返回邀请码；响应带 `Cache-Control: no-store`。
- `POST /api/matches/{id}/join?code=...` 使用邀请码加入房间，同样接受 `{"deck":[卡牌ID...]}`，规则与创建时相同。
  无效牌组不会消耗邀请；访客牌组不会改变房主的起手牌。双方加入后再进行换牌。
- `GET/POST /api/matches/{id}` 读取状态或提交动作，需要 `Authorization: Bearer <playerToken>`。
  `POST` 的可选 `expectedRevision` 为无符号整数，零也是有效值；省略时保留原有调用行为。
  网页始终发送此字段，其他调用方也应发送以防止旧指令作用于新局面。
  它与选择响应的 `stateRevision` 不同：前者校验整个对局，后者与 `requestId`、`actionId`
  一起校验具体待选请求。`POST /api/matches/{id}/mulligan` 同样支持 `expectedRevision`。
- `GET /api/matches/{id}/replay` 使用同一玩家令牌读取完整事件与状态帧，响应不缓存。
  每帧包含 `revision`、`eventCount` 和该玩家视角的 `state`，其中 `eventCount` 是截至此帧的累计事件数。
  第 i 帧的事件为 `events.slice(frames[i-1]?.eventCount ?? 0, frames[i].eventCount)`。
  对手手牌始终隐藏，待选择请求仅对所属玩家可见；无效操作不会增加状态帧。
  融合与手牌变身事件按令牌视角隐藏卡牌身份，保留数量、事件序号及原有帧边界。

持有者的卡牌实体可带 `fusion`：包含 `enabled`、`usedThisTurn`、`totalCost`、
`distinctKinds` 和有序 `materials`（卡牌 ID 与原始费用）。这些材料信息不会发送给
对手，也不会因来源卡进入战场而公开。对战详情与录像详情均显示该视角下的融合记录。

模式选择请求的候选可带 `labels`，键为语言代码，值为卡牌作者提供的纯文本。
网页优先使用 `chs`，其次 `eng`，以可换行的单选项显示；缺失时只显示稳定编号。
选择与确认分开，键盘可以用原生单选控件切换，发送指令或重连期间禁止改选。
文本不作为 HTML 执行，也不用于推断规则或选项可用性。

录像按房间和玩家座位分别保存，局面变化时同步完整历史，不因状态轮询追加重复事件。
播放器支持逐帧牌桌、首尾跳转、时间轴、暂停及 0.5/1/2/4 倍速，当前帧事件与战场、手牌、资源同步。
点击卡牌可查看该帧的身材与进化卡图。旧记录缺少事件边界时仅显示完整事件日志，不推测事件归属。
浏览器本地存储最多保留最近 20 条录像；存储不可用或容量不足时提示，新数据继续保留在当前页面内存中。
已保存的录像可在刷新后独立回放，但不会替代规则服务中的对局状态。卡组草稿也保存在本地。

录像数据与事件标签的回归测试：`node --test scripts/replays.test.mjs`（仓库根目录，Node.js 22.18+）。

卡组页面支持搜索、职业/类型/费用筛选、卡牌详情、增减数量和费用曲线，保存一个本地牌组草稿。
网页创建或加入房间时始终提交当前草稿，非法草稿会返回编辑页，不会替换成练习牌组。
邀请链接先打开房间页，可编辑牌组后再确认加入。尚无对应卡图的卡牌显示缺图占位；卡背仅用于隐藏手牌与牌堆。
