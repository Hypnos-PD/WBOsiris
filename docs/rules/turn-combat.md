# 回合与战斗规则草案 0.1

本文是 `wbo-standard-0.2.0` 的实现前规则草案。它先固定可以被测试和回放验证的
回合边界；战斗结算仍需补充关键词时序后才能实现。本文中的 `own` 和 `oppo` 相对
当前回合行动方解释，事件事实中的 `Side` 使用稳定的全局玩家标识。

## 1. 回合状态

```text
Turn = {
  active: "own" | "oppo",
  number: non-negative integer
}

Phase = "main"
```

`number` 表示当前完整回合编号。初始行动方进入第 `1` 回合；行动方从 `oppo` 切换
到 `own` 时编号加一。当前原型只允许 `own` 提交玩家动作；完整双方面板接入后，
提交者必须等于 `Turn.active`。

初始状态已经完成牌局设置，不自动发出 `turn_start` 或抽取首张牌。测试若要验证
回合开始效果，必须使用 `advance turn_start <side>` 驱动规则时点；正式回合只能
通过 `end_turn` 到达该时点。

## 2. 结束回合

`end_turn` 必须满足：

- 提交者是当前行动方；
- 阶段为 `main`；
- 没有其他动作或选择请求正在结算。

非法 `end_turn` 不改变状态、事件序号、死亡批次号或 RNG。合法动作不支付资源，且
在回合切换完成前保持一个动作事务。回合边界触发器产生选择请求时，原行动方仍是
Continuation 中的动作控制者；所有待处理触发和选择完成后才提交切换。

一次合法结束回合按以下顺序执行：

1. 发出 `turn_ended <active>` 事实并排空该事实产生的触发队列。
2. 将行动方切换为另一方；若从 `oppo` 切换为 `own`，`number` 加一。
3. 执行新行动方的回合开始准备。
4. 发出 `turn_started <active>` 事实并排空触发队列。

回合开始准备按以下固定顺序执行：

1. `maxpp` 增加一点，最大不超过 `10`。
2. `pp` 设置为当前 `maxpp`。
3. `combo` 设置为 `0`。
4. 所有该行动方的护符 `engaged` 设置为 `false`。
5. 所有该行动方场上护符的 `countdown` 减少一点；减至零的护符形成一个死亡批次，
   先整体离场，再按现有死亡批次规则排入谢幕曲。
6. 从该行动方牌组顶部抽一张牌。牌组为空时本次抽牌无效果，不消费 RNG；疲劳伤害
   尚未纳入本草案。

`turn_started` 监听器看到的是上述准备步骤完成后的状态。准备步骤产生的事实和触发
   队列必须在 `turn_started` 之前按规则检查点排空；其中任何选择都暂停同一个回合
   动作，不得提前接受下一玩家动作。

本草案暂不改变 `ep` 或 `sep`。它们的初始值、获得方式、每局上限和是否在回合开始
   恢复需要单独提升规则条款后才能实现，运行器不得自行增加。

## 3. 事件与恢复

回合事实使用现有测试事实形式：

```text
turn_end <side>;
turn_start <side>;
```

实现内部事件名保持 `turn_ended` 和 `turn_started`，测试 DSL 映射为上述稳定事实。
事件的 `Sequence` 单调递增；回合准备中的死亡事实使用新的 `BatchID`，并遵守死亡
批次的整体离场、事实提交和谢幕曲入队顺序。

暂停的回合动作必须在 Continuation 中额外保存：

```text
turnTransition: "none" | "ending" | "starting"
transitionSide: "own" | "oppo"
```

恢复时不得根据当前 `Turn` 猜测是否已经切换。`ending` 只能继续结束当前行动方，
`starting` 只能继续准备已记录的下一行动方；非法组合必须在状态改变前拒绝。

## 4. 战斗动作边界

`attack <source> into <target>` 的通用动作协议已在语法中登记，但在以下规则明确前，
模拟器继续将其声明为 `unsupported_feature`：

- 随从何时获得攻击资格，以及召唤、进化、变形后是否可以立即攻击；
- 每个随从每回合的攻击次数和攻击状态重置时点；
- `ward`、`intimidate` 对攻击目标候选的完整约束；
- 随从攻击主战者与攻击随从的伤害顺序，是否同时造成伤害；
- `rush`、`storm`、`bane`、`drain` 的触发时点和失效条件；
- 伤害、生命归零、死亡批次、谢幕曲和战斗结束事件的精确顺序；
- 主战者生命归零后的终局事实及后续动作处理。

战斗规则确定后，应先为每个边界写 `.wbotest` 场景和事件事实序列，再实现合法性
预检、攻击结算和回合内攻击状态。未定义的关键词不能由客户端或动画层补全。

## 5. 实施顺序

1. 为 `turn_ended`、`turn_started`、PP、抽牌、倒计时和 `end_turn` 增加测试场景。
2. 扩展 Continuation 保存回合转换进度。
3. 实现回合准备和边界触发队列。
4. 冻结战斗伤害和关键词时序后，再实现 `attack`。
5. 最后将 `evolve` 接入手动进化费用、目标状态和回合限制。
