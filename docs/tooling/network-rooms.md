# 网络房间与恢复

接口层面的完整消息定义见[对局线协议](wire-protocol.md)；本页只讲房间的使用与恢复流程。

先在卡组页选中合法的 40 张牌组，再创建房间。房主可在等待界面或房间页复制邀请链接。
对手打开链接后，选好自己的牌组并点击加入。双方分别确认起手换牌后进入对战。
等待中的房间不发起手牌，也不预先决定先后手。对手提交合法牌组后，服务端为本局生成独立
随机种子并随机分配先后手；房主与客方都可能先手。种子不通过对局、邀请或录像接口公开。
换牌界面和回合按钮显示当前玩家的先后手，后手能量与进化解禁按这一分配执行。
双方确认前手牌保持不变；两方选择按固定顺序统一结算，发送确认的先后顺序不改变结果。
入场后可在牌桌右上角选择「认输」并确认；认输立即结束本局，录像会记录认输方与胜方，
待选择的效果也会一并取消。
浏览器不支持自动复制、或拒绝剪贴板权限时，界面会选中邀请链接，供手动复制。

房间页的「本机保存的房间」列出当前浏览器保存的房间与席位。通过「恢复房主席位」或
「恢复客方席位」可重新进入等待、起手换牌、进行中或已经结束的对局。恢复不会重新
提交牌组，也不会重新执行已经完成的动作。房间状态仍以规则服务返回的数据为准。

同一浏览器可以保存一个房间的两个席位。恢复地址使用 `seat=own` 或 `seat=oppo`
明确指定席位，刷新后保持该席位。没有 `seat` 的旧地址优先读取有效房主凭据，再读取
有效客方凭据；显式指定席位时不会自动切换到另一方。对局状态中的 `own`、`oppo`、
行动方与胜方均已按当前观察者转换，原始事件的方位则通过 `viewer` 解释。
`state.firstPlayer` 也按观察者转换：`own` 表示自己先手，`oppo` 表示自己后手；
它与凭据中的房主席位 `own`、客方席位 `oppo` 分开使用。完整回合在后手结束后递增。

## 保存与连接状态

浏览器以 `wbo-match-<房间 ID>-<席位>` 保存凭据，内容包括房间 ID、席位、玩家令牌和
最近进入时间。旧版没有时间字段的有效凭据仍可恢复。坏记录会跳过，原始内容保留。
邀请链接只包含房间 ID 与邀请码，不包含玩家令牌；双方玩家令牌各自用于身份验证。

刷新等待中的房间时，服务端会向通过认证的房主重新返回邀请码。客方、公开房间列表
和录像响应不会收到邀请码。对手加入后，双方状态响应都不再返回邀请信息。

短暂断网、请求超时或服务错误会进入自动同步。提交动作时未收到响应，会先重新读取
状态，再开放操作，不自动重发动作。服务明确返回 `401`（凭据失效）或 `404`（房间
不存在）时，客户端停止轮询，显示原因并提供返回房间页的入口；可从本机记录再次尝试
恢复，或创建新房间。

当前规则服务将房间保存在内存中，服务进程重启后旧房间不会保留。浏览器凭据仅能
恢复服务仍持有的房间。已经保存到浏览器的录像仍可在录像页查看。
终局牌桌提供「再开一局」入口，会使用当前牌组创建新的等待房间；原房间与录像仍保留。

## 练习模式与观战

不想等对手时用卡组页的「练习对战（对 AI）」：服务端用 `mode: "bot"` 建房，
客方席位由内置策略接管（默认 `greedy`）。建房即开局，AI 的换牌自动保留起手；
人类的每一次提交之后，服务端会把 AI 推进到再次轮到人类为止。对局响应里的
`bot: true` 表示对手是 AI，`botError` 非空时说明 AI 驱动失败（应当记录并反馈）。

任何已开始的房间都可以申请观战凭据（`POST /api/matches/{id}/spectate`）：
观众只能读状态、公开事件与推送流，看不到双方手牌，也不能提交动作。
实时界面或外部工具可以订阅 `GET /api/matches/{id}/stream`（SSE）。

## 大厅

客户端首页是大厅：**整页背景是主界面插图**——背景图 + Spine 立绘的合成（`idle` 待机、
点击播 `tap_01..04`），相机窗口按 `skeletonScale × prefabScale × 布局缩放` 换算，
会按窗口比例挑 `aspectLayouts` 里最接近的一套。选中的插图作为整个内容区的背景，
可以像游戏主界面那样随时更换（大厅的「更换主界面」，选择记在本机）。

立绘有两个来源，前端优先用打包进来的那份：

1. **打包素材**：`node scripts/bundle_illustrations.mjs` 把 WBArts 的主界面插图
   （默认 `home` 类型 40 张，约 675 MB）**逐字节**复制进 `web/public/assets/home/`，
   并生成 `index.json` 清单。素材不压缩、不转码，图集页名保持原始 PNG。
2. **规则服务**：内置的 `hi_1001` 永远可用；`wbo serve` 另外扫描
   `--illustration-root`（默认 `../WBArts/data`）里的 `home-illustration/*`，
   通过 `GET /api/illustrations` 列出、`/illustration-assets/…` 只读地提供素材
   （含 `home-illustration-picts` 的缩略图）。

spine 运行时在加载阶段会把 logo 与转圈画进 canvas，因此前端在加载完成前不显示
canvas，避免那个加载圈。

大厅其余部分：`公开房间`列表（可加入的房间给「去加入」，进行中的房间给「观战」）、
快速加入（房间 ID + 邀请码）、当前牌组与当前房间的状态卡。大厅与其它页面共用左侧导航，
牌桌是独立页面，页面之间不再互相叠放。

## 验证

```bash
go test ./internal/server
go test -race ./internal/server
node --test scripts/match-storage.test.mjs scripts/match_connection.test.mjs
```

服务端测试检查房主恢复邀请码、公开信息与客方权限边界；前端测试检查旧凭据恢复、
双席位选择、邀请地址、状态修订同步和失效房间停止轮询。
开局回归还覆盖等待期间不泄露起手、随机初始化失败后重试、并发加入只发牌一次、
两种先后手及换牌确认顺序无关性。模拟器仍可显式指定种子和先手，用于可复现的规则测试。
