# 网页牌组库

卡组页可保存最多 100 副命名牌组。通过「选择牌组」切换编辑对象，新建、复制或导入后
会选中新牌组；每次修改成功保存后才更新界面。名称长度为 1–60 个字符，允许同名构筑。
删除后可在当前卡组页撤销，至少保留一副牌组。

「练习牌组」选中已有的完整练习构筑，或创建一副新牌组。已经修改过的构筑会保留。
未满 40 张的草稿也能保存和导出。当前卡池会检查数量、职业、同名卡上限和可编入牌组
资格；未知卡牌会显示编号并允许移除。只有通过检查的牌组能创建或加入房间。

主页与房间页显示当前选中的牌组。创建或加入房间时提交这副牌组；对局开始后，切换
牌组库中的选择用于下一次建房或加入，对局中已经提交的牌组保持独立。

## 导入与导出

「导出牌组」下载 `.wbo-deck.json` 文件。「导入牌组」读取该文件并创建独立副本。
文件不包含房间凭据、对战状态或本地牌组标识。例如，下面是一副两张卡牌的草稿：

```json
{
  "format": "wbo-deck",
  "version": 1,
  "name": "中立草稿",
  "cards": [10001110, 10001120]
}
```

`cards` 按顺序列出卡牌编号，重复编号表示多张卡牌。导出使用整数，导入也接受十进制
正整数字符串。文件须不超过 100,000 字节，列表最多 1,000 项，以便恢复旧的超量构筑。
导入仅检查文件结构和版本，构筑合法性由当前卡池检查；错误文件不会覆盖已存牌组。

## 本地保存与恢复

牌组库保存在当前浏览器、当前站点的 `wbo-deck-library` 中，结构版本为 `1`，包含
`activeId` 与 `decks`。每副牌组包含独立 `id`、`name` 和字符串编号数组 `cards`。
首次使用会迁移旧的 `wbo-deck-cards`，保留顺序、重复卡牌及空草稿，同时保留旧键。
没有旧数据的新用户会在卡池加载完成后获得练习牌组。

保存空间不足或存储不可用时，界面提示「本次修改未应用」，继续保留上次成功保存的
内容。可在恢复存储访问后重新读取并再次操作。其他标签页的存储更新会同步到当前页，
保存前也会比较最近读取的数据；检测到变化时拒绝覆盖，并要求重新读取。

无法解析或版本不支持的数据不会被自动覆盖。「恢复异常牌组库」可下载原始数据，或
先写入 `wbo-deck-library-backup-<唯一标识>` 本地备份，再重建空库。备份失败会终止
重建。备份文件保留原始 JSON 字符串，供修复数据使用，不属于单副牌组导入格式。
浏览器清理站点数据会清除本地牌组与本地备份，长期保留的构筑可导出为文件。

模型与存储回归测试：`node --test scripts/deck-library.test.mjs`。
