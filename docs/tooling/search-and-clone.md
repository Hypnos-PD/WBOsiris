# 决策点克隆与搜索预算

这份文档记录"搜索住在 Go 里"所需的引擎能力、实测成本，以及由此得到的搜索预算结论。
面向 WBDecima 的决策功能与后续 MCTS/PIMC 实现。

## 决策点存档（idle continuation）

`Continuation` 原本只支持"挂起中"的会话（有待处理选择）。搜索与重放需要从**任意主动作边界**
克隆，所以续局格式增加了决策点形态：

- `pending` 为空即表示决策点存档：没有待处理选择、没有未结算的栈、没有未排空的触发；
- 恢复出来的会话直接停在某一方的主动作边界，`LegalActionsFor` 立刻可用；
- 原挂起形态的编码/恢复路径未改动，行为与校验保持原样。

`internal/search.Clone(cards, session)` 就是"编码 → 解码 → 恢复"这条路径的封装。

## 实测成本（i9-11900H，单线程）

| 操作 | 优化前 | 优化后 |
| --- | ---: | ---: |
| `Clone`（编码+解码+恢复） | 78 ms | **5.0 ms** |
| 恢复（解码+重建会话） | 84 ms | **4.5 ms** |
| 编码（生成续局 JSON，约 30 KB） | 0.34 ms | 0.34 ms |
| 随机推演（克隆 + 双方随机打到终局） | 146 ms | **58 ms** |

优化手段是 **`runtimeIndexFor`**：IR 块索引（`indexBlocks`）与卡池指纹（`runtimeCardPackHash`）
只取决于卡池内容，却在每次新建会话与每次恢复时重算。现在按卡池对象缓存一份（卡池在进程内不可变）。

连带收益（同一套卡池、同样的对局结果）：

| 场景 | 优化前 | 优化后 |
| --- | ---: | ---: |
| `wbo selfplay --games 300 --policy greedy` | 46.8 s | **17.7 s** |
| 环境协议 `reset` 单局耗时 | 90–119 ms | **11 ms** |

对局分布与胜负完全一致（先手 157 / 后手 143、平均 9.6 回合），说明这是纯成本优化。

## 搜索预算结论

- 一次克隆 5 ms ⇒ 单进程每秒约 200 次克隆；再加一次价值网络前向，**"若干候选动作 + 价值截断"的浅搜是可行的**。
- 但随机推演到终局要 58 ms ⇒ **靠随机 rollout 的完整 MCTS 不可行**（每秒不到 20 次评估）。
- 因此搜索的形状应该是：少量候选（比如 8–32 个）+ 用价值网截断 + 必要时并行多进程；
  真要更深的搜索，需要把克隆成本再压一个数量级（原生深拷贝，而不是 JSON 往返）。

## 后续可选优化（按性价比）

1. 原生 `Session.Clone()`：去掉 JSON 往返与实例重建，目标 < 100 µs。
2. 增量化：只复制被动作影响的部分（撤销/重放），避免整局快照。
3. 多进程并行推演：现在每个进程独立，16 核可以线性扩展，先做这个最省事。
